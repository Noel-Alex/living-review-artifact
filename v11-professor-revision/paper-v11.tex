\section{Introduction}
A review comment refers both to a location and to a concern. When the code is revised, the location may move while the concern remains, or the concern may be addressed while most of the quoted code survives. Review threads routinely outlive the lines they were written on. In the five open-source projects of our real-history study, \wpeOutdated{} of \wpeThreads{} inline review threads on merged pull requests (\wpeOutdatedPct\%; 95\% pull-request cluster interval \wpeOutdatedLo--\wpeOutdatedHi\%) were marked outdated by GitHub, and \wpeNullLinePct\% of the outdated threads could no longer be placed on any line (Section~\ref{sec:motivation}). These counts describe professional projects and GitHub's diff-based outdating, not student work, but they show how often a reviewer must reconstruct where an earlier remark now applies.

\sys{} is the resubmission model of a capstone review portal in which faculty supervisors review a team's code and report over several versions. Two problems must be kept apart. The \emph{technical} problem is to re-find each anchored piece of code in the next version and to report how it changed. The \emph{educational} problem is whether carrying feedback forward helps supervisors re-review and helps students act on feedback; feedback-literacy research motivates retaining and revisiting comments \cite{carless2018feedback,winstone2017supporting}, but does not show that relocating annotations improves either. This paper addresses the technical problem and the issue-state rules that connect it to supervision. It measures no learning, comprehension, re-review time or faculty-workload outcome; those require a consented classroom study.

Content-bearing anchors, fuzzy matching, diff-based position tracking, syntax-aware differencing and region mapping across commits are established \cite{brush2001robust,w3c2017annotation,asaduzzaman2013lhdiff,falleri2014fine,reiss2008tracking,hu2026codemapper}, and review tools already port or outdate comments \cite{gerritporting,github2018outdating}. We therefore do not claim a new matching principle. The contribution is a \emph{safety-oriented, version-aware feedback workflow}: relocation results become explicit evidence labels; the labels decide whether an issue returns to its supervisor; only the supervisor resolves an issue; and the evaluation measures, in the terms that matter for that workflow, how often the matcher hides a change or points the supervisor at the wrong code.

We fix the evaluation objective before reporting results. A wrongly placed issue misdirects a supervisor, whereas a missing location is visible and prompts a manual search. Outcomes are therefore ordered by consequence: (i) \emph{missed re-checks}, changed or deleted code that is not returned to the supervisor, and \emph{silent misplacements}, an issue shown on the wrong code without a re-check request, are the primary safety failures; (ii) \emph{lost} anchors cost a manual search; (iii) \emph{unnecessary re-checks} cost attention. Each is reported separately, with its denominator, and is never folded into a single accuracy figure without stated weights. We do not set a pass/fail limit: the acceptable rate is an institutional choice, so we report the trade-off frontier instead.

\textbf{Research questions.} \textbf{RQ1} (location): how accurately is anchored code re-found on controlled edits, real Python revision histories and an independent human-annotated multi-language benchmark, compared with conventional review behaviors, a contextual line tracker, a syntax-aware differencer and a state-of-the-art region mapper? \textbf{RQ2} (safety): how often does carry-forward fail to return changed or deleted code for re-check, or misplace an issue silently, and which mechanisms cause these failures? \textbf{RQ3} (design and calibration): how do search scope, tier order and similarity threshold affect accuracy and safety, and does a threshold chosen on some projects transfer to others? \textbf{RQ4} (stress and scale): how do duplicated, short, re-indented and compound-edited anchors, repeated resubmissions, multi-anchor issues and large repositories change these results, and what do targeted safety guards cost? \textbf{RQ5} (locator transfer): does the safety-oriented workflow improve the reliability of an already strong locator, and does keeping the reviewed quotation make identity transitions across many versions visible? \textbf{RQ6} (state contract): does the implemented issue lifecycle match its specification, in particular that no system action resolves an issue?

The paper makes four contributions. (1)~A content-based code-anchor relocation cascade that distinguishes identical, content-matched, moved, changed and removed code (Section~\ref{sec:design}), with three guards derived from its failure analysis, and evidence that the locator-independent part of this layer (the change labels, the indentation and copy guards and the issue-state policy), placed over the stronger locator CodeMapper, makes it safer without changing its placement (Section~\ref{sec:locator}). (2)~A human-controlled review-issue lifecycle, comprising carry-forward with lineage, dismissal memory and anchored media notes, specified as a transition relation and checked against its implementation (Sections~\ref{sec:design}--\ref{sec:impl}), with an identity rule that keeps the reviewed quotation across versions (Section~\ref{sec:identity}). (3)~An evaluation of relocation accuracy and safety on controlled transformations, real Python histories and external human-annotated data (Sections~\ref{sec:method}--\ref{sec:stress}). (4)~An analysis of the relocation--deletion trade-off and of cross-project threshold calibration, including the negative result that empirically safety-constrained thresholds did not transfer between project groups.

\section{Background and Related Work}\label{sec:related}

\subsection{How Often Review Comments Outlive Their Lines}\label{sec:motivation}
To quantify the problem in a public setting, we collected every merged pull request with at least one inline review thread from Requests, Flask, Click, HTTPX and Rich between January 2022 and June 2026, through GitHub's GraphQL interface \cite{githubgraphql}. Of \wpeThreads{} inline threads, \wpeFollowedPct\% were followed by at least one further commit to the pull request, and \wpeOutdatedPct\% (pull-request cluster bootstrap 95\% interval \wpeOutdatedLo--\wpeOutdatedHi\%) were marked outdated; \wpeNullLinePct\% of the outdated threads no longer had a line in the current diff. GitHub marks a thread outdated when the diff hunk it was written on changes \cite{github2018outdating}; outdated threads remain readable, but the reviewer must find where the concern now applies. The sample is professional open source, the snapshot reflects force-pushes and squashes, and resolution does not show that a concern was fixed, so the figures motivate rather than measure the educational problem.

\subsection{Robust Annotation Anchoring}
Robust document annotation predates this system. Brush et al.\ examined annotation positioning after document edits \cite{brush2001robust}; Phelps and Wilensky developed robust intra-document locations \cite{phelps2000robust}. Hypothesis describes quote-based fuzzy anchoring \cite{csillag2013fuzzy}, and the W3C Web Annotation Data Model specifies text-quote and text-position selectors \cite{w3c2017annotation}. For code, recent systems keep annotations attached as programs evolve: Meta-Manager records the provenance of edits in the editor \cite{horvath2024metamanager}, and Magic Markup re-tags document-external markup with a language model \cite{misback2024magic}. These systems target a single developer's working copy and its edit stream; \sys{} receives whole submitted versions without an edit stream and must decide, for each earlier concern, whether its supervisor needs to look again.

\subsection{Code Review and Warning Tracking}
Modern review combines line-specific discussion with human judgment \cite{bacchelli2013expectations,sadowski2018modern}. Review tools differ in how comments survive a revision, and a fixed-line model describes none of them fully. GitHub keeps a comment on its line while the line is unchanged and marks it outdated when the exact anchoring line changes \cite{github2018outdating}. Gerrit ports unresolved comments to a newer patch set by calculating their position in the new file, and attaches them at file level when no position can be calculated; ported comments look like ordinary ones, and resolved comments are not ported \cite{gerritporting}. GitLab can be configured to resolve diff threads automatically when a push makes them outdated \cite{gitlabautoresolve}, the opposite of the human-only resolution adopted here. CodeReviewQA tests whether language models understand review comments by asking them to recognize the change type, localize the change and identify the solution, on 900 curated examples in nine languages \cite{lin2025codereviewqa}. It localizes the code a comment asks to change within one version, whereas \sys{} must find where already-reviewed code went in the next. Static-analysis warning trackers retain issue identity across versions and remember earlier review decisions about warnings \cite{avgustinov2015tracking,li2024tracking,spacco2006tracking,sonarqube}; their findings are produced by the analyzer, so an issue that disappears from the analysis can be treated as fixed, whereas a supervisor's concern cannot. ViolationTracker builds precise violation histories with introduced, fixed, deleted and reopened states \cite{yu2023violationtracker}; there too a violation is fixed when the analyzer stops reporting it. Whether a revision touched the reviewed code and whether the concern about that code still holds are different questions; a \sys{} change label answers only the first, so it only requests a check. Table~\ref{tab:related} compares documented behaviors. Apart from GitHub's outdated flag, which the suggestion oracle measures, we did not benchmark these products; our conventional baselines reimplement their documented policies, and product documentation supports the table, not performance claims.

\subsection{Source Differencing and Region Mapping}
Line differencing underlies many revision tools \cite{myers1986ond}. Our matcher uses Python's sequence matcher, which extends the Ratcliff--Obershelp approach \cite{ratcliff1988pattern,pythonsequence}. LHDiff combines line content and context to track source lines \cite{asaduzzaman2013lhdiff}; related work tracks changed lines \cite{canfora2007identifying}, surveys program-element matching \cite{kim2006program} and tracks source locations \cite{reiss2008tracking}. ChangeDistiller and GumTree provide syntax-aware differencing \cite{fluri2007change,falleri2014fine}; a refactoring-aware syntax-tree differencer built on RefactoringMiner adds multi-mappings and commit-level diffs, with a benchmark of node mappings from bug-fixing and refactoring commits \cite{alikhanifard2024astdiff}. Origin analysis considers renamed, merged and split entities \cite{godfrey2005using}. History trackers follow named program elements through a commit history with refactoring awareness: CodeShovel builds method histories \cite{grund2021codeshovel}, CodeTracker tracks methods and variables \cite{jodavi2022codetracker} and code blocks \cite{hasan2024blocktracking}, and HistoryFinder revisits the oracles these tools were evaluated on \cite{islam2025historyfinder}. They track syntactic elements, whereas a review anchor is an arbitrary range of lines. ReCite finds Linux-kernel comments whose referenced function was renamed or removed, traces the reference through the history and proposes a repair with a language model for people to accept \cite{sun2026recite}. The closest recent work is CodeMapper, which maps an arbitrary code region from one commit to another, language-independently, by combining several git diff algorithms, movement detection and text search with context-aware similarity selection \cite{hu2026codemapper}. ReviewAnchorBench turns bot-written review suggestions into executable mapping cases: a target is represented by its quoted lines and its proposed replacement, and located, ambiguous and deleted outcomes, as well as abstention, are scored against oracles \cite{fu2026reviewanchorbench}. It measures the recovery of one anchor across one revision; \sys{} keeps an issue's state across many revisions and leaves every decision to the supervisor. Section~\ref{sec:rab} runs our locators on it. These methods answer \emph{where is this code now}. None defines what a reviewer should be told about the change, or what happens to a concern when the answer is uncertain; that is the part \sys{} adds, and Section~\ref{sec:external} compares the matchers directly.

\subsection{Issue Lifecycles}
Issue trackers, review discussions and warning trackers all carry items across time with states such as open, resolved and closed. The relevant distinction is who may close an item and on what evidence. Analyzer-driven trackers may close an issue the analysis no longer reports; some review tools may close a thread when its lines change \cite{gitlabautoresolve}. \sys{} restricts every closing transition to the supervisor and lets relocation evidence move an issue only towards \lbl{needs re-check}. We do not claim that human-controlled resolution or persistent dismissal is new in isolation; the contribution is binding them to relocation labels with an explicit, checked transition relation (Section~\ref{sec:design}).

\subsection{Educational Feedback}
Feedback research motivates specific, actionable comments \cite{hattie2007power,shute2008focus}, and feedback literacy concerns how learners interpret and use them \cite{carless2018feedback,winstone2017supporting}. Keuning et al.\ found that programming-feedback tools support diagnosing mistakes more than planning corrections \cite{keuning2018systematic}. This literature establishes that revisiting feedback matters; it does not establish that relocating annotations improves students' understanding or response to feedback, and we know of no study that does. That causal link is the open question this paper's technical results make testable, not one they answer.

\subsection{Versions and Anchors}
A submission version $V_t$ contains files $(\pi,T)$ and extracted report text. A code anchor is $a=(\pi,s,e,c,q)$: path, first and last line of an original span of height $k=e-s+1$, whole-file SHA-256 digest and quoted text. Let $\qbar$ be the nonblank quoted lines with surrounding whitespace removed. The quotation is matching evidence, not a globally unique identifier of a program entity. An issue may hold up to twelve anchors. Report anchors store quoted text; media attachments can refer to an issue, a code range or the review. Their bytes are content-addressed. The original benchmark scores only code anchors and checks file/start location. Section~\ref{sec:ranges} separately evaluates AST source-line extents on surviving real-history targets.

\begin{algorithm}[t]
\caption{Relocate a code anchor $a = (\pi, s, e, c, q)$}
\label{alg:relocate}
\small
\begin{algorithmic}[1]
\Require new files $F$ (path $\mapsto$ (digest, text)); previous text $P$ of $\pi$; threshold $\theta$
\If{$\pi \in F$ \textbf{and} digest$(F[\pi]) = c$} \Return $(\pi, s, e, \lbl{identical})$
\EndIf
\State $\qbar \gets$ stripped non-blank lines of $q$; $k \gets e - s + 1$
\If{$\pi \in F$}
  \State $R \gets$ starts of runs equal to $\qbar$ in $F[\pi]$
  \If{$R \neq \emptyset$}
    \State $s' \gets \arg\min_{x \in R} |x - s|$
    \State \Return $(\pi, s', \cdot, s' = s\ ?\ \lbl{content-match} : \lbl{moved})$
  \EndIf
  \State $p \gets$ image of $s$ under the line diff of $P$ and $F[\pi]$; $r \gets \max(10, 2k)$
  \State $(\rho, s') \gets \max_{x \in [p-r,\, p+r]} \mathrm{ratio}(\qbar, \mathrm{window}(F[\pi], x, k))$
  \If{$\rho \geq \theta$} \Return $(\pi, s', s' + k - 1, \lbl{changed})$
  \EndIf
\EndIf
\For{each other path $\pi'$ in $F$, in sorted order}
  \If{$\qbar$ is a run in $F[\pi']$ at $x$} \Return $(\pi', x, \cdot, \lbl{moved})$
  \EndIf
\EndFor
\State \Return \lbl{removed}
\end{algorithmic}
\end{algorithm}

\subsection{Relocation}
Given $V_{t+1}$ and, when available, the previous text of $\pi$, relocation returns a new position and a label (Algorithm~\ref{alg:relocate}, Fig.~\ref{fig:cascade}). Tier~1 accepts an untouched file. Tier~2 searches $\qbar$ as a contiguous run of stripped non-blank lines in the same file and takes the occurrence nearest the old start. Tier~3 handles edits in place. It maps the old start line through a line diff \cite{pythonsequence} of the previous and new file to an expected start $p$, scores every window of height $k$ starting within $p \pm r$, $r = \max(10, 2k)$, by the similarity ratio of the joined stripped lines, and accepts the best window if the ratio reaches $\theta$ (deployed default $0.85$). Tier~4 searches $\qbar$ in the other files, in sorted path order. Tier~3 runs before tier~4 so that an edited block is recognized in place rather than matched to an identical copy elsewhere, and its window stays near the diff-predicted line to avoid distant look-alike code; Section~\ref{sec:design-results} measures both choices. A report anchor is matched in the same way against the sentences of the new report, with ratio threshold 0.8.

For normalized lines joined by a single space, let $u$ and $v$ be the resulting quotation and candidate strings. The fuzzy score is
\begin{equation}
\operatorname{ratio}(u,v)=\frac{2\sum_i m_i}{|u|+|v|},
\end{equation}
where $m_i$ are the matching-block lengths returned by Python's sequence matcher with its automatic junk heuristic disabled. Only full-height windows are considered. Starts are scanned in ascending order and the first maximum is kept; exact-run distance ties likewise select the first run. If the previous file text is unavailable, the predicted start defaults to the old start. These deterministic details decide ambiguous matches and are part of the evaluated implementation.

\subsection{Labels and Their Limits}
Table~\ref{tab:labels} defines the five labels. The word \emph{exact} in earlier versions of this work suggested more than the matcher establishes, so we use \lbl{content-match} for equality after normalization. Normalization is what lets an anchor survive blank-line and formatting edits, but in Python it also hides indentation, which carries meaning: a statement dedented out of a conditional keeps its stripped text and can keep its line number while its behavior changes. A \lbl{content-match} or \lbl{moved} label is therefore textual evidence, not semantic evidence. A second limit concerns copies. When the original is edited or deleted and an identical copy exists elsewhere, tiers 2 and 4 can return the copy as \lbl{moved}; because \lbl{moved} keeps the issue's state, the change is not returned to the supervisor. Sections~\ref{sec:safety} and~\ref{sec:stress} measure both limits.

\subsection{Proposed Safety Guards}\label{sec:guards}
The failure analysis of Section~\ref{sec:safety} motivated three switches on the deployed cascade, and the compound-edit stress test a correction to one of them. They are evaluated alongside it under protocols whose text and code hashes were recorded before any held-out run (Section~\ref{sec:method}); the deployed cascade remains the system of record.
\begin{itemize}
\item \textbf{Indentation guard (IG).} When a normalized run is accepted at tier 2 or 4, the leading-whitespace widths of its non-blank lines (tabs expanded to eight columns) are compared with the quotation's, both relative to the first line and in absolute base indentation. For Python files any difference turns the label into \lbl{changed} with reason \emph{layout}; for other languages only a relative difference does. Placement is unchanged.
\item \textbf{Pre-existing-copy guard (AG).} At tier 2 a run that starts exactly at the diff-predicted line is preferred over the run nearest the old start. When a tier-2 or tier-4 run is accepted anywhere other than the predicted line, the guard counts occurrences of $\qbar$ in the old and new versions of the candidate file. A genuine move introduces the text, so only an increased count yields a clean \lbl{moved}; otherwise the placement is kept but re-check is requested with reason \emph{pre-existing copy}. The previous version's files are already loaded by carry-forward, so the guard needs no new input.
\item \textbf{Insertion fix (AGi).} AG as first specified flagged every clean insertion directly above an anchor: the pinned diff mapping sends the old start of such an anchor to the first inserted line, so the unmoved anchor never sits at its predicted start (Section~\ref{sec:compound}). AGi is AG with one change: a run at the line to which the diff maps the anchor's own first line also counts as the predicted start. It needs only the returned window and the two versions of the file, so it applies to the output of any locator (Section~\ref{sec:locator}).
\item \textbf{Variable-height window (VW).} Tier~3 also scores windows of heights $h\in[\max(1,k-d),\,k+d]$, $d=\max(1,\lceil k/2\rceil)$, so that statements that grow or shrink can be recovered with their new extent. Ties prefer the predicted start, then the original height.
\end{itemize}
None of the guards proves identity. Two copies introduced in the same revision defeat AG, a copy inserted just below the original can make the diff align the original's lines with the copy and so defeat AGi, and IG is a layout signal, not an equivalence test. We also tested a provenance rule (AG2) that accepts a window by where its lines came from in the diff instead of by copy counts. It removed more unnecessary requests but could not tell a move from an edited original with an identical copy elsewhere, and on the held-out duplicate suite it missed nearly as many re-checks as no guard at all (Section~\ref{sec:locator}). Content alone cannot decide which of two identical copies is the reviewed one; it can only decide when to ask.

\subsection{Keeping the Reviewed Text}\label{sec:identity}
When tier 3 accepts a \lbl{changed} window, carry-forward replaces the anchor's quotation with the matched text, and the next version is matched against that text. A wrong fuzzy match therefore becomes the reference for every later version, and a later \lbl{content-match} label then certifies only that the wrong code did not change again. We evaluate an identity rule (ID) that keeps the quotation the supervisor reviewed, $q_0$, unchanged beside the current one, $q_t$. Relocation still tracks $q_t$, but two checks use $q_0$. Every \lbl{changed} hop must also reach similarity 0.5 to $q_0$ (the calibrated threshold, Section~\ref{sec:design-results}); otherwise the transition is uncertain, the anchor is reported removed and its issue returns, so the anchor cannot drift step by step into unrelated code. And the request is computed against $q_0$: an issue returns for re-check whenever the located code differs from what the supervisor reviewed, however many versions ago that was. The interface would show $q_0$ beside $q_t$. A supervisor's confirmation sets a new $q_0$; the replay in Section~\ref{sec:prefixes} assumes no supervisor action. ID needs no particular locator and is evaluated over both the cascade and CodeMapper.

\subsection{Complexity}\label{sec:complexity}
Let the anchored file have $L$ lines, the version $N$ lines in $F$ files, the anchor $k$ lines and its joined quotation $q$ characters. Tier~1 compares stored digests in $O(1)$. Tier~2 normalizes the file and scans for runs in $O(L + ck)$, where $c$ counts lines equal to the first quoted line, so $O(Lk)$ in the worst case. Tier~3 first maps the old start through a line diff, quadratic in $L$ in the worst case for Python's sequence matcher \cite{pythonsequence}, and then scores $2r+1$ windows at $O(q^2)$ each, giving $O(L^2 + rq^2)$ with $r=\max(10,2k)$; VW multiplies the window term by $2d+1$. Tier~4 normalizes and scans every other file, $O(Nk)$. One anchor therefore costs $O(L^2 + rq^2 + Nk)$ in the worst case, and a review with $A$ anchors $O\!\left(A(L^2 + rq^2 + Nk)\right)$, because the implementation neither caches normalized files nor indexes lines across anchors. The $ANk$ term dominates for anchors whose code has disappeared from a large repository: every other file is scanned. A line index keyed by the first normalized line would reduce tier~4 to the cost of verifying candidate runs. Section~\ref{sec:scale} measures these costs on large repositories.

\subsection{Issue States}
When a new version arrives, active issues (\lbl{open}, \lbl{accepted} or \lbl{needs re-check}) are copied into its review with relocated anchors and a lineage reference. Any \lbl{changed} or \lbl{removed} anchor requests re-check; otherwise the previous active state is retained. No relocation transition resolves an issue. A finding raised again is matched to a carried issue by category, title and overlapping evidence, so that a carried concern is not duplicated; the carried issue takes the fresh evidence, an active one returns for re-check, and a resolved or dismissed one keeps its state. A newly raised finding is also compared with the findings dismissed on the immediately preceding version, by category and the first paragraph of its description (first 200 normalized characters); a match is created already dismissed, with a note naming that version. The key is a heuristic: findings that share an opening paragraph are conflated, rewording evades it, and the memory lapses if a version does not raise the finding (Section~\ref{sec:statecheck}). Fig.~\ref{fig:states} summarizes the lifecycle and Table~\ref{tab:transitions} specifies it.

\subsection{Media Notes and Release}
Notes attached to carried issues follow their issue; notes pinned to code are re-found by the cascade. A note whose code is gone is kept on the review as a whole and records where it was (``it was on \emph{path:lines}''). At publication, notes on issues the supervisor shares are listed in each student's immutable feedback snapshot, and the file route serves a note only to students whose snapshot lists it.

\subsection{Deployment}
The portal runs as a small set of containers. A web container is the single front door: Caddy serves the static web client used by faculty and students and proxies API calls. The api container runs the FastAPI application, which owns authentication, authorization on every protected route, validation and all durable state. A worker and a scheduler run Celery tasks on a Redis queue: analysis of a submission (rule checks, a language-model review of the submission and the partner claim-to-code tracer, whose results arrive as signed bundles) and the composition of the review. PostgreSQL holds versions, review issues, anchors, revisions, the change journal and publications; schema changes are forward-only migrations. Submitted archives, extracted files and media notes are kept in an artifact store addressed by their SHA-256 digest. An optional assistant runs as its own service and edits review points only through journaled, undoable tool calls (Section~\ref{sec:statecheck}). Relocation needs no extra component: its matching core uses Python's standard-library sequence matcher \cite{pythonsequence}.

\subsection{Data Model}
A report version records its predecessor, so the versions of a project form a chain (Fig.~\ref{fig:model}). The files of a version are rows with a safe path, a SHA-256 digest and a text flag; their bytes stay in the artifact store, and only text files below a size limit are read for relocation. Each version has one review document, which holds the supervisor's review: issues, a summary, stated limitations and a carry record (from which version issues were carried, how many need a re-check, how many dismissals were remembered). An issue has a status among \lab{open}, \lab{accepted}, \lab{needs re-check}, \lab{resolved} and \lab{dismissed}, a severity, a category, a title and body, and up to twelve anchors stored as JSON in its evidence. A carried issue's origin reference has the form \texttt{carry:v$t$:id}; it records the issue's lineage and makes composition idempotent. Every edit of an issue appends an attributed revision, and a write must name the revision it was based on, so concurrent edits are detected rather than lost. Media notes are attachment rows that point to bytes stored once under their digest; a note is anchored to an issue, to a code range or to the whole review, and is private or shared. A per-version change journal records every write by faculty, the system or the assistant, and supports undo. At release, the approved shared points are frozen into a packet per student.

\begin{algorithm}[t]
\caption{Compose the review of version $t{+}1$}
\label{alg:compose}
\small
\begin{algorithmic}[1]
\Require version $t{+}1$ with files $F$ and report text; review $D_t$ of version $t$; new findings $\Phi$
\State lock version $t{+}1$; $D \gets$ its review document (created if absent)
\State $K \gets$ keys (category, first description paragraph) of issues \lab{dismissed} in $D_t$
\For{each issue $i \in D_t$ that is \lab{open}, \lab{accepted} or \lab{needs re-check}}
  \If{$D$ already holds an issue with origin \texttt{carry:v$t$:}$i$} \textbf{continue} \EndIf
  \State $A \gets$ anchors of $i$ re-found in $F$ (Algorithm~\ref{alg:relocate}) or in the report text
  \State $s \gets$ \lab{needs re-check} \textbf{if} any anchor in $A$ is \lab{changed} or \lab{removed} \textbf{else} status of $i$
  \State add a copy of $i$ to $D$ with anchors $A$, status $s$ and origin \texttt{carry:v$t$:}$i$
\EndFor
\For{each finding $f \in \Phi$}
  \If{a carried issue has $f$'s category and title and an overlapping anchor}
    \State refresh its anchors; if it is active, set it to \lab{needs re-check}
  \ElsIf{the key of $f$ is in $K$} \State add $f$ as \lab{dismissed}, naming the version where it was dismissed
  \Else \State add $f$ as \lab{open}
  \EndIf
\EndFor
\State carry media notes: with their carried issue, or re-found by Algorithm~\ref{alg:relocate}
\State record the carry counts for the banner; mark $D$ ready
\end{algorithmic}
\end{algorithm}

\subsection{Review Composition}
When a version arrives, the worker analyses it and the review is composed (Algorithm~\ref{alg:compose}). Composition first locks the version's row, because the faculty home page, open project tabs and the worker may all compose the same version at once. Carry-forward comes first, so that a finding the new analysis raises again is matched to the issue the supervisor already has rather than duplicated. Carry-forward reads only the immediately preceding version's review; if that review was never composed, its issues reach the next version only after it is composed and the later version recomposed. If the new finding has the same category and title as a carried issue and an overlapping anchor, the carried issue keeps the supervisor's wording and takes the fresh evidence; an active issue asks for a re-check, and a resolved or dismissed one keeps its state. If it matches an issue the supervisor dismissed on the previous version, it is created already dismissed, with a note naming that version. Media notes follow: a note attached to a carried issue moves with it; a note pinned to code is re-found by the cascade and, when its code is gone, stays on the whole review with a note of where it was. A copy is a new row that points to the same stored bytes. Finally the carry counts are recorded, and the review page shows them as a banner (``$N$ points carried over $\cdot$ $M$ need a re-check''), with a ``From version~$n$'' tag on each carried issue and a plain-language note on each anchor.

\subsection{Trials and Ground Truth}
A trial picks a file and a 1--10-line anchor. It starts on a nonblank line, contains at least 30 non-space characters, has distinct lines and has a quotation unique in the source file. One of twelve edit operators supplies a reference start location or a gone target (Table~\ref{tab:edits}). Inserted filler is copied from other corpus files. Up to twenty-five additional sampled files accompany the edited version. There are \nPerOp{} trials per operator and \nTrials{} per seed. The main and replication seeds are \seedMain{} and \seedRep. A separate tuning seed, 7, supplies 150 trials per operator. The default threshold was fixed for the reported main runs; no externally registered protocol is documented here. These are controlled text mutations of real source, not necessarily valid or behavior-preserving Python programs.

\subsection{Baselines}
The comparators are implemented policies, not executions of commercial review products. \emph{Fixed line} retains the original path and span and returns no match if the normalized quotation differs there. \emph{Diff drift} follows equal line-diff blocks but returns no match if an anchored line changes or the range ceases to be contiguous. \emph{Exact quote} searches the same file for the nearest stripped quotation. These three policies do not attempt fuzzy recovery of edited quotations. \emph{Cascade v1}, an earlier internal version, is a stronger comparator than these three policies: it searches other paths before fuzzy matching, searches the whole original file and uses $\theta=0.75$. It differs from the final default in three respects, so its default comparison is compound rather than a single-factor ablation. Equal-threshold comparisons separate out threshold choice but still change order and scope together. The original LHDiff binary is not available to us. GumTree's official release and the pinned CodeMapper artifact \cite{hu2026codemapper} are evaluated on the external benchmark (Section~\ref{sec:external}). A separately pinned third-party hybrid tracker is evaluated on controlled trials in Section~\ref{sec:externaltracker} and retained real-history observations in Section~\ref{sec:realtracker}.

\subsection{Outcomes and Metrics}
A location is correct if its file and starting line equal the reference, or if it returns no match when the reference target is gone. It is lost if the target survives but no location is accepted, and wrong if it is placed elsewhere. The original scoring function does not check the returned end line, range overlap or continued relevance of the review concern; the added range analysis in Section~\ref{sec:ranges} addresses the first two on a defined subset. The benchmark's \emph{silent error} means a returned location labeled unchanged under its fixed-height normalized-quote definition when the quote changed or the location is wrong; for the cascade this corresponds to an erroneous \lbl{content-match} label (deployed identifier \texttt{exact}). A \lbl{moved} label can still fail to trigger re-check, so Section~\ref{sec:safety} reports missed re-checks and silent misplacements as separate rates. Synthetic proportions use nominal 95\% Wilson score intervals \cite{wilson1927probable}.

For paired correctness, $b_{01}$ counts trials correct only for the final cascade and $b_{10}$ counts trials correct only for the comparator. McNemar's framework compares the discordant pairs \cite{mcnemar1947note}. Conditional on $d=b_{01}+b_{10}$, the null assigns each direction probability $1/2$. The archived implementation computes the two-sided exact binomial tail
\begin{equation}\label{eq:pairedexact}
p=\min\left\{1,\;2\sum_{j=0}^{\min(b_{01},b_{10})}\binom{d}{j}2^{-d}\right\},
\end{equation}
with $p=1$ when $d=0$. This specifies the calculation reported in Table~\ref{tab:overall}. These nominal trial-level calculations do not model source-file or project dependence. Runtime is measured per relocation on one laptop core, not per complete review.

A placement can be right while its change status is wrong, and the converse. Wrong placement and lost anchors are reported separately throughout, because a wrong location misdirects the supervisor while a missing one is visible. \subsection{Dependence-Aware Uncertainty}
Trials share source files, and real-history observations share commit pairs and projects. Besides nominal Wilson intervals, we report cluster-bootstrap 95\% intervals from 10,000 fixed-seed resamples of source files (controlled), commit pairs and, separately, projects (real histories), for headline accuracies and every paired difference, together with the sign of each per-project difference. A conclusion is stated as directional only if it survives the project-level interval. Every percentage is rounded independently from its raw counts, so the parts of a partition may sum to 99.9 or 100.1.

\subsection{Protocols and Held-Out Evidence}
Every new analysis in this revision followed a written protocol whose text and executable-code hashes were recorded, with a timestamp, before the analysis it governs; these are local records, not external preregistrations. Before any new result was produced, a reproduction gate re-ran the archived methods and required per-observation agreement with all \nTrialsAll{} archived controlled trials and all \smRealCasAccN{} real-history observations, including the \smRealTrkExecFail{} execution failures of the external tracker; the gate passed. The real-history observations had been inspected in earlier revisions, and the safety guards were designed after examining the real-history missed re-checks, so all guard results on these histories are retrospective. The held-out evaluations of the guards are the stress suites generated after their code was fixed (Section~\ref{sec:stress}), the external human-annotated benchmark (Section~\ref{sec:external}) and the student-authored repositories (Section~\ref{sec:student}).

\subsection{Calibration Objectives}
Threshold calibration previously maximized the number of correct outcomes. Because the stated objective ranks safety failures first, we also report safety-constrained calibration, which maximizes accuracy subject to limits on the missed re-check rate and on the rate at which deleted code is reported present, and leave-one-project-out calibration over all nine projects (Section~\ref{sec:design-results}). The oracle-excluded observations cannot enter any calibration without independent labels, so every threshold is calibrated on the oracle's decidable subset only.

Fig.~\ref{fig:threshold} shows the threshold study on the tuning seed. The whole-file variant attaches more removed anchors to look-alike code at thresholds that recover genuine edits. In the final design, $\theta = 0.85$ keeps both tuning curves high; above about 0.9, genuine edits increasingly return no match. These comparisons do not separate window scope from tier order; the factorial analysis of Section~\ref{sec:design-results} does.

\subsection{Independent Hybrid Tracker}\label{sec:externaltracker}
The three policy baselines do not attempt general recovery of edited lines. To test whether the aggregate advantage persists against an independently implemented contextual tracker, we added an exploratory comparison with the MIT-licensed Go implementation by Oselvar \cite{oselvarlhdiff}. This implementation cites LHDiff and combines line-content Levenshtein similarity with surrounding-context cosine similarity. It is not the original paper authors' binary: its documentation states that it omits SimHash optimization and line-splitting support. We pinned revision \texttt{5a9f7fd} and used its command-line defaults: four context lines, content/context weights of 0.6/0.4 and the implementation's 0.45 combined-similarity cutoff. No threshold was tuned on our trials.

The adapter asks for a mapping of the old anchor's first line in the same path. A missing first-line mapping returns no match. This follows the original benchmark's path-and-start scoring; neither method receives credit for end-range validity. The tracker has no cross-file search or review-state policy. We therefore compare location outcomes only, and report cross-file and within-file strata separately. The original corpus, operators and seeds are unchanged. Trial metadata and the cascade outcomes are checked against the independently reproduced runs, and all 7,200 tracker outcomes are retained. Upstream tests and the adapter's one-based coordinate check pass. Go and Python timings are not compared, since the adapter adds inter-process communication and the implementations use different runtimes.

\subsection{Commit Pairs and Anchors}
We formed pairs of consecutive commits (a small revision) and non-overlapping pairs ten commits apart (a second, larger revision horizon). In each pair, anchors are statements of 1--10 lines directly inside function bodies of Python files the later commit modified, renamed or deleted, under the constraints of Section~\ref{sec:method}. We drew two samples per pair. The \emph{uniform} sample takes up to 8 anchors (at most 3 per file). The \emph{edit-targeted} sample takes the same number from statements that overlap a hunk of the commit's diff, a deliberately enriched sample; diff overlap does not itself establish that a statement changed. Each version holds the full project tree of the later commit, so moved code can land anywhere.

% Syntax-tree oracle (shared by both papers); mirrors oracle() in real_history.py.
\begin{algorithm}[t]
\caption{Syntax-tree oracle for an anchored statement}
\label{alg:oracle}
\small
\begin{algorithmic}[1]
\Require statement $x$, the $i$-th statement of function $g$ (qualified name) in file $\pi$ of the old version; new version $V'$
\State $T(\cdot) \gets$ syntax tree without positions, formatting or comments
\State $\pi' \gets$ new path of $\pi$ (Git rename detection)
\If{$g$ is defined once in $V'[\pi']$}
  \State align $T$ of the body statements of $g$ in both versions (sequence matching)
  \If{$x$ is aligned to an equal statement $y$} \Return location of $y$ \EndIf
  \If{$x$ has an offset-matched $y$ of the same type in an equal-cardinality replacement} \Return location of $y$ (edited) \EndIf
  \If{$x$ is in any other replacement} \Return \emph{undecidable} \EndIf
\EndIf
\State $H \gets$ function-body statements of $V'$ with tree $T(x)$
\If{$|H| = 1$} \Return location of its element (moved) \EndIf
\If{$|H| > 1$} \Return \emph{undecidable} \EndIf
\If{$g$ is gone and a changed file has a function similar to $g$} \Return \emph{undecidable} \EndIf
\State \Return \emph{gone}
\end{algorithmic}
\end{algorithm}

\subsection{Syntax-Tree Oracle}
The reference procedure uses Python's abstract syntax tree (Algorithm~\ref{alg:oracle}). Functions are identified by qualified name, and their top-level body statements are aligned by normalized trees. Equal statements give a new start. In an equal-cardinality replacement hunk, the statement at the corresponding offset is accepted if its AST node type matches the old statement's type; this can pair unrelated statements. Deleted targets can be found as a unique equal tree elsewhere. Ambiguous replacements, copies and renamed-and-rewritten functions are excluded for all methods: \rExcluded{} observations (\rExcludedPct\%), including \rNmEx{} unequal-cardinality replacements. Both the oracle and matcher use sequence alignment, on different representations. The recorded manual audit covers 40 in-house decisions, stratified between preserved and difficult classes; 39 were accepted and one pairing was doubtful. That audit is neither a blinded multi-rater validation nor evidence of oracle accuracy on public projects. After finding a start, the harness defines changed content by comparing an old-height normalized window there with the old quotation. Thus its \emph{edited} class is not identical to the set of changed AST statements (Section~\ref{sec:definitionaudit}).

\emph{Direction of reference error.} The reference calls a target unchanged only when the quoted lines, ignoring whitespace, stand at its location and occur once in that file; each of the \refdirCertified{} real-history targets it called unchanged passes this check. The check shows that the text there is unchanged, not that it is the reviewed code. For \refcopyAligned{} of these targets identity rests on an equal syntax tree at the aligned position of the same function and for \refcopyPaired{} on same-type pairing; the other \refcopyRelocated{} left their function and were placed on the unique equal statement elsewhere in the new version. Reading the earlier version of the public histories (tools/v11/audit\_reference\_copies.py), \refcopySuspect{} of the \refcopyChecked{} relocated targets landed where an identical statement already stood before the revision, so the reference may have taken a pre-existing copy for the reviewed code; the deployed cascade requested no check on any of them. Counted as hidden misses they raise the deployed miss rate from \refdirMissPct\% to \refcopyMissPctChecked\%, and counting also the \refcopyUnavailable{} relocations in our own projects, whose earlier versions this check could not read, gives \refcopyMissPctWorst\%. In the other direction, the same-type pairing of replaced statements decides \refdirPaired{} of the \refdirChanged{} changed or deleted targets. Of the deployed cascade's \wpaMissTotal{} real-history misses (Section~\ref{sec:safety}), \refdirMissAligned{} rest on an equal syntax tree at the aligned position, \refdirMissPaired{} on same-type pairing and \refdirMissDeleted{} on a deletion. Even if every pairing and deletion behind a miss were wrong, and the copy the cascade found were the true target, the miss rate would fall to \refdirBoundPct\%. Under these reference errors the deployed miss rate lies between \refdirBoundPct\% and \refcopyMissPctWorst\%. The bounds cover missed re-checks only: identification errors can move placement accuracy either way and can hide unnecessary re-checks. The student-authored repositories use the same reference unchanged.

\subsection{Sensitivity to the Definition of Change}\label{sec:definitionaudit}
The stored rows retain both the oracle's alignment event and the quote-window class. These answer different questions. A statement may expand beyond the old span while leaving the first old-height window unchanged; conversely, reformatting an equal AST statement can change that window. We re-counted the recorded default labels using the oracle's replacement or deletion event as a second reference definition, without rerunning the matcher or changing its threshold (Table~\ref{tab:definitionaudit}).

There are 2,364 same-type AST-replacement observations and 144 deletion observations. Of these 2,508 reference events, 52 were labeled \lbl{content-match} or \lbl{moved} and therefore did not request re-check: recall is 97.9\%. Eleven replacement observations were labeled \lbl{content-match}. Twenty-one replacements were classified as preserved by the original window definition (11 \lbl{content-match} and 10 \lbl{moved}). In the other direction, 293 aligned equal-tree observations were classified edited because the quote window differed. The two denominators are not nested, so the 97.9\% and 98.7\% rates must not be subtracted as a paired performance improvement.

This is a sensitivity analysis of the same retained observations, including repeats. The oracle's replacement marker is not a human judgment of semantic relevance and can itself contain pairing errors. Nevertheless, the disagreement is sufficient to bound the original interpretation: zero errors under a quote-window definition does not establish that no structural statement change was labeled \lbl{content-match}. The no-auto-resolution invariant remains separate from both matching metrics.

\subsection{Verification Against Complete Source Revisions}\label{sec:sourcecontext}
Saved quotations alone cannot establish whether a reference points into the correct revision. We recovered the recorded heads of all nine histories and reconstructed each pair from its first-parent index and horizon. The five public heads were fetched at their recorded revisions with depth 400. Their first-parent counts matched the archive: 626, 448, 589, 400 and 1,093. Full head identifiers, traversal lists, shallow boundaries, pair revisions and file hashes are retained in the verification artifact. Private source remained local. No project source was executed.

We separately reran the original sampling and AST-reference procedure from the pinned histories, omitting only matcher evaluation and timing. In-house repositories used the original shared random stream and order; each separately collected public repository restarted seed 20261028. All 15,064 ordered retained observations matched the saved selection, source coordinates, quotation text and reference class. The 2,205 exclusions and every per-project exclusion-reason count also matched. This verifies deterministic regeneration under Python 3.12.14, not independent human validity of the reference rule. The retained per-project reports distinguish this check from the complete-source coordinate check and the saved-row aggregation.

All 15,064 old quotations matched the reconstructed old revision. Every assigned reference's saved old-height target window also matched the new revision. For 14,917 non-deleted observations, the old and referenced new function-body statements could be uniquely recovered and compared structurally: all 2,364 replacement markers had different syntax trees, while the 12,553 aligned/relocated markers had equal trees. Three further observations had ambiguous same-line statement extraction in this additional checker; 144 had no assigned surviving target. These checks validate recorded coordinates and structural relations. They do not establish that a same-type replacement is the same conceptual entity, independently prove deletion, or replace human adjudication.

The complete source explains the 21 observations where the quote window is preserved but the reference statement changes. Nineteen observations (18 distinct pair/anchor targets) grow beyond the old range. The remaining two change decorators above a function definition, outside the line interval the original AST-based sampler used. Together these are 20 distinct targets, since one growing target occurs in both sampling schemes. Eleven observations retain a \lbl{content-match} label: ten growing statements and one decorator change. The other ten are labeled moved. These are concrete limits of the quoted interval, rather than evidence that every such change violates the matcher's normalized-text contract.

For example, a Click revision renames the decorator call from \texttt{resultcallback} to \texttt{result\_callback} above an otherwise unchanged function \cite{clickdecoratorcase}. The AST includes the decorator; the sampled quote begins at the function's definition line and omits it. The \lbl{content-match} label is therefore compatible with identical quoted lines, but cannot certify an unchanged complete statement. Similarly, retaining the old number of lines omits a growing statement's new suffix. These examples motivate evaluating complete source extents and relevant context separately from quote preservation.

We also prepared a source-based review packet with expected targets and matcher outcomes withheld. It contains 50 cases stratified equally across the original five reference classes and the 20 distinct quote/AST disagreements, shuffled in a recorded order. The unblinding key is separate. No independent reviewer responses have been collected, so the packet is preparation for validation, not a human-validation result.

\subsection{Independent Tracker on Real Histories}\label{sec:realtracker}
We extended the pinned hybrid tracker from Section~\ref{sec:externaltracker} to the same 15,064 retained real-history observations. The input is the complete old file and its corresponding new path, using Git rename detection as for the original simple policies. The reference target path is never supplied as a search hint. Mapping the old anchor's first line gives a candidate start; scoring retains the original file/start reference. Thus this experiment compares location recovery, not the review-state policy or complete returned ranges. It remains conditional on the original oracle and exclusions.

The unmodified tracker dependency crashes on some non-BMP Unicode characters: its Levenshtein implementation indexes a 65,536-element table with a larger code point. We reproduced that failure with a minimal changed emoji line. A failed process is discarded before another file pair is evaluated, preventing partially mutated global state from affecting later requests. Neither source text nor the matching algorithm is patched. Failed file pairs are recorded as execution errors, not silently removed or relabeled as a successful no-match. The run completes with 143 affected observations across 37 distinct source-content file pairs, all in the public group. The 143 observations comprise 85 uniform and 58 edit-targeted cases. A regression check confirms both explicit failure reporting and a fresh successful request afterward.

Keeping persistent issue state independent of the chosen tracker allows that component to be evaluated or replaced without treating a recovered location as proof of resolution.

\section{RQ2: Safety of Carry-Forward}\label{sec:safety}
Safety is a defining property of \sys{}, so we report it as a family of rates rather than as a single count. For a set of targets with reference classes, let $C$ be the targets whose code was edited or is gone, $P$ the content-preserved targets, $S$ the targets that survive and $A$ all targets, and let $R=\{\lbl{changed},\lbl{removed}\}$ be the labels that request re-check. Then
\begin{align}
\text{missed re-check} &= |\{c\in C : \ell(c)\notin R\}|\,/\,|C|,\label{eq:missed}\\
\text{false re-check} &= |\{p\in P : \ell(p)\in R\}|\,/\,|P|,\\
\text{silent misplacement} &= |\{x\in W : \ell(x)\notin R\}|\,/\,|A|,
\end{align}
where $W\subseteq A$ are the targets placed at a wrong location, and the lost rate is the share of $S$ for which no location is returned. The re-check rule is the deployed one: \lbl{changed} and \lbl{removed} request re-check; \lbl{identical}, \lbl{content-match} and \lbl{moved} keep the issue's state. Earlier versions of this work scored every label other than the deployed \texttt{exact} as flagged; that adapter counted a \lbl{moved} label as a re-check and therefore could not observe the failures below. Placement (file and start line on surviving targets) and classification (label against reference class) are scored separately, because a location can be right while its change status is wrong.

\subsection{Missed Re-checks Are Rare but Not Absent}
On controlled edits and real histories, no observation receives a \lbl{content-match} label when the code inside its quoted span changed; edits around the span are outside this check, as the applied review suggestions show. That is true but incomplete. On real histories, \smRealCasMissK{} of \smRealCasMissN{} edited or gone targets (\smRealCasMissPct\%; Wilson 95\% interval \smRealCasMissLo--\smRealCasMissHi\%) are not returned for re-check, and \smRealCasSilentK{} of \smRealCasSilentN{} targets (\smRealCasSilentPct\%) are placed on the wrong code without a request. On the controlled main seed the corresponding counts are \smCtlCasMissK{} of \smCtlCasMissN{} and \smCtlCasSilentK{} of \smCtlCasSilentN{}. The cascade never requested re-check for preserved real-history content (\smRealCasFalseK{} of \smRealCasFalseN{}); its cost on real histories is instead \smRealCasLostPct\% lost anchors, which request re-check and leave the supervisor to search manually.

Every one of the \smRealCasMissK{} real-history misses carries the \lbl{moved} label (Table~\ref{tab:missedcases}). In \wpaMissCross{} cases tier~4 found the quotation in another file and in \wpaMissSame{} cases tier~2 found it elsewhere in the same file, while the original had been edited (\wpaMissEdited{}) or deleted (\wpaMissGone{}). The mechanism is a pre-existing identical copy: the matcher follows the text, and the text still exists. \wpaMissSingleLine{} of the \wpaMissTotal{} anchors are a single line, the kind of short statement most likely to recur verbatim. This is the identical-code ambiguity anticipated in Section~\ref{sec:design}, and it is the dominant safety failure of the method; Section~\ref{sec:stress} shows that it becomes frequent when copies are common.

\subsection{What a Missed Re-check Means for the Supervisor}
A missed re-check does not hide an issue. The issue stays active and visible in the new review, with its carried quotation, its new location and the plain-language note ``the code it points to moved; it is shown at its new place''. What is lost is the prompt: the issue is not marked \lbl{needs re-check}, and the location it shows is a copy of the old code, so a supervisor who trusts the location sees the old code apparently unchanged. A silent misplacement is the same failure seen from the location side. Whether supervisors notice such cases was not measured. The interface's only mitigation is that the carried quotation is shown beside the new location. That quotation is the text at the previous version, not necessarily the one the supervisor reviewed (Section~\ref{sec:integrity}), and showing it does not replace an empirical check.

\subsection{Scope of the Guarantee}
The state contract guarantees, for the evaluated implementation, that no system action marks an issue \lbl{resolved}; Section~\ref{sec:statecheck} verifies this against every status write in the code. It does not guarantee that every change is detected or that every anchor is placed correctly. Those are empirical properties of the matcher, bounded by the rates above for the evaluated distributions only.

\subsection{Safety--Utility Trade-off}
Configurations trade the outcomes against one another rather than improving all of them. Lowering the threshold to 0.5 cuts real-history lost anchors from \smRealCasLostPct\% to \smRealCalLostPct\% and missed re-checks from \smRealCasMissPct\% to \smRealCalMissPct\%, but raises wrong placements from \smRealCasWrongPct\% to \smRealCalWrongPct\%, nearly all of which do request re-check. The contextual tracker has the lowest real-history missed and silent rates of the evaluated matchers but cannot follow code between files. Under an additive cost model with the cost of a lost anchor fixed at one and log-spaced weights for the other outcomes, no method minimizes cost across the whole weight range (Fig.~\ref{fig:effort}); the ranking changes with the relative price of a silent misplacement and a manual search. We therefore state the deployment objective explicitly: minimize missed re-checks and silent misplacements first, and only then manual searches and unnecessary re-checks. Under that objective the guards of Section~\ref{sec:guards}, not a lower threshold, are the relevant intervention. The weights are illustrative; no faculty cost was measured.

\section{RQ3: Design Factors and Calibration}\label{sec:design-results}

\subsection{The Default Does Not Dominate Its Predecessor}
On real edit-targeted public histories, the earlier cascade v1 relocates more targets than the final default (\smPubTgtVoneAccPct\% versus \smPubTgtCasAccPct\%; internal \smIntTgtVoneAccPct\% versus \smIntTgtCasAccPct\%), although the final default leads on controlled edits (\smCtlCasAccPct\% versus \smCtlVoneAccPct\%). The reversal is a primary result, not a footnote: the default threshold of 0.85 was tuned on controlled token edits and is too strict for naturally edited statements, on which it relocates only \thetaEditedEightyFive\% of edited statements correctly (Table~\ref{tab:tradeoff}). v1 also differs in tier order, search scope and threshold, so the comparison does not isolate any single choice.

\subsection{Factorial Ablation}
To separate the choices, we evaluated every combination of tier order (local fuzzy search before cross-file exact search, as deployed, or after it, as in v1), search scope (a window around the diff-predicted line or the whole file) and threshold $\theta\in\{0.50,0.55,\dots,0.95\}$ on both controlled seeds and all real-history observations. The two corners matching the deployed cascade and v1 reproduce the archived outcomes exactly. Averaged over thresholds, searching the whole file instead of the local window lowers the rate at which deleted code is correctly reported as removed by \wpaScopeGoneInt{} points on internal and \wpaScopeGonePub{} points on public projects: a distant look-alike is accepted in place of an honest \lbl{removed}. Running cross-file exact search before local fuzzy search raises missed re-checks by \wpaOrderMissInt{} and \wpaOrderMissPub{} points, because an edited block is then matched to an identical copy elsewhere, which is exactly the failure analyzed in Section~\ref{sec:safety}. Both deployed choices are therefore supported on safety grounds. Accuracy alone favors lower thresholds, and at equal thresholds the final design leads v1 in all nine projects after calibration; on internal projects the equal-threshold advantage of \wpaEqThrDiff{} points has a project-cluster interval of $[\wpaEqThrLo, \wpaEqThrHi]$, so its direction is not established there. Table~\ref{tab:factorial} reports the averaged contrasts, and the evidence package retains every cell; these are matched contrasts on shared observations, not randomized experiments.

\subsection{The Relocation--Deletion Trade-off}
Lowering the threshold recovers more edited statements and reports fewer deleted ones correctly (Table~\ref{tab:tradeoff}). At $\theta=0.50$, \thetaEditedFifty\% of edited statements are relocated but only \thetaGoneFifty\% of deleted statements are reported removed; at the default 0.85 the figures are \thetaEditedEightyFive\% and \thetaGoneEightyFive\%. No threshold is best for both. A deleted statement that is relocated attaches a concern to different code, which is the more consequential failure, whereas an edited statement that is not relocated becomes a visible \lbl{removed} anchor and requests re-check. This trade-off is intrinsic to similarity thresholding and is the central practical decision when deploying the method.

\subsection{Cross-Project Calibration}
In leave-one-project-out calibration over the nine projects, choosing the threshold that maximizes accuracy on eight projects selects $\theta=\wpaLopoTheta$ in all \wpaLopoFolds{} folds, both for the threshold alone and for the full factorial cell, and for both training objectives (Table~\ref{tab:lopo}). The selection is stable across projects. Applied to public edit-targeted histories, $\theta=\wpaLopoTheta$ relocates \smPubTgtLopoAccK{} of \smPubTgtLopoAccN{} targets (\smPubTgtLopoAccPct\%), against \smPubTgtCalAccPct\% at the archived calibrated value of 0.50 and \smPubTgtCasAccPct\% at the default. These histories had been inspected in earlier revisions, so this is retrospective transfer evidence, not a prospective held-out result.

\subsection{Safety-Constrained Calibration Did Not Transfer}
Calibrating for accuracy is misaligned with the stated objective, so we also chose thresholds on the four internal projects to maximize accuracy subject to a missed re-check rate of at most $\alpha$ and a deleted-reported-present rate of at most $\beta$, for $\alpha\in\{1,2,5\}\%$ and $\beta\in\{5,10,20\}\%$. Of the design and limit combinations, \wpaConstrFeasible{} were feasible on the internal projects and \wpaConstrInfeasible{} were not. Evaluated once on the public projects, \wpaConstrViolate{} of the \wpaConstrFeasible{} feasible choices violated at least one of their own limits. For example, $\theta=\wpaConstrTheta$ met an internal 20\% cap on deleted code reported present but reached \wpaConstrPubGonePresent\% on public edit-targeted observations. Empirical rates from one group of projects therefore do not bound the rates in another; a deployment that needs a guaranteed limit would require a calibration method with explicit transfer assumptions, and the projects here do not justify exchangeability.

\subsection{Choosing a Threshold in Practice}
For an institution with no history of its own, the evidence supports three steps. Keep the local search scope and the deployed tier order, which are favoured on safety grounds in every stratum. Treat $\theta$ as a policy choice between relocating edited code and reporting deleted code honestly: $\theta\approx\wpaLopoTheta$ maximized accuracy in every held-out project, whereas the default 0.85 favors honest removal. Monitor the outcomes after deployment, since supervisors' own corrections of misplaced anchors are the data a local calibration would need.

\section{RQ4: Stress Conditions and Safety Guards}\label{sec:stress}
The controlled benchmark samples anchors that are long and unique enough to be found again, and its twelve edit types each receive equal weight. Its aggregate of \smCtlCasAccPct\% is therefore a score on a balanced benchmark of single, controlled transformations, not an estimate for naturally occurring revisions; on its four content-changing edit types alone the default reaches \ctlChangedAccPct\%. This section deliberately constructs harder conditions. Their rates describe the constructed cells and are not estimates of how often such cases occur; real-history prevalence is given by Section~\ref{sec:safety}. All stress inputs were generated, and the guards' code fixed, before evaluation on the held-out seed (protocol in the artifact).

\subsection{Indentation}
Normalization hides indentation (Section~\ref{sec:design}). To measure the consequence we constructed Python edits that preserve every normalized line but change nesting: a statement dedented out of its block, statements absorbed into the preceding block, one inner line of a multi-line anchor changing level, and a block moved one level with its header. Every generated file parses, and an edit counts as behavior-changing when the abstract syntax tree of the enclosing scope changes. The deployed cascade requested no re-check for any of these: \bIndentMissDeployed{} of \bIndentSemanticN{} behavior-changing edits kept their state. With the indentation guard none did (\bIndentMissIG{} of \bIndentSemanticN{}). The guard's cost appears on layout-only edits whose syntax tree is unchanged: it requested re-check for every continuation-line re-alignment (\bIndentFalseIG{} of \bIndentLayoutN{} layout-only edits overall).

The same experiment exposes a defect in the original benchmark. Its \emph{re-indent} operator, scored as an unchanged success, indents an anchor by four spaces without regard to syntax; of \BOriginalIndentTotalMain{} trials on the main seed, \BOriginalIndentInvalidMain{} produced files that no longer parse and \BOriginalIndentASTChangedMain{} produced parseable files with a changed syntax tree (replication: \BOriginalIndentInvalidReplication{} and \BOriginalIndentASTChangedReplication{} of \BOriginalIndentTotalReplication{}). Its \casReindent\% score measures normalized-text relocation, not safe handling of re-indented Python. We retain the original scores for comparability and report this qualification with them.

Real histories contain few such cases. Among all retained observations, \bRealIndentReturned{} returned spans match the old quotation after normalization but differ in indentation, and at the oracle's own locations \bRealIndentOracle{} do, all of them with unchanged statement trees. Indentation changes that alter behavior are thus rare in the studied histories, and their real-history frequency, unlike their construction, is not established here.

\subsection{Duplicated, Short and Low-Information Anchors}
Supervisors often annotate short statements such as \texttt{return result}, an import or a repeated validation line. We constructed two stress suites. In the duplicate suite an identical copy of the anchored code is inserted near or far, above or below, or in another file, while the original is kept, edited, deleted or moved. In the short suite, one-line anchors are stratified by how often their normalized text recurs in the file and passed through the original edit types.

Duplicates are the cascade's weakest condition (Table~\ref{tab:duplicates}). The deployed cascade missed \bDupMissDeployed\% of the needed re-checks and placed \bDupSilentDeployed\% of the issues on the wrong code without a request; tier~2 chooses the copy nearest the old start, and a copy inserted just above the original occupies exactly that position. The pre-existing-copy guard reduced these to \bDupMissAG\% and \bDupSilentAG\%. It cannot help when the copy and the move are introduced in the same revision. One-line anchors fared better but still missed \bShortMissDeployed\% of needed re-checks, concentrated in the most frequently recurring lines. These results support a design change at annotation time as well as at relocation: when a supervisor anchors a line whose normalized text recurs in the file, the interface should ask for a longer selection.

\subsection{Guard Costs on Real Histories}
Each guard requests re-checks that the deployed cascade would not. Per 100 content-preserved real-history references, the indentation guard added \bIGExtraReal{} requests and the pre-existing-copy guard \bAGExtraReal{} at the default threshold, rising to \bIGExtraPubTgt{} and \bAGExtraPubTgt{} on public edit-targeted references; the variable-height window added none. On the \wpaMissTotal{} archived missed re-checks, the pre-existing-copy guard left \bArchivedMissAG{} unrequested and the combination of all three guards at $\theta=\wpaLopoTheta$ left \bArchivedMissAllCal{}. Because these cases motivated the guard, this is a mechanism check, not held-out evidence; the held-out evidence is the stress suites above and the external benchmark in Section~\ref{sec:external}.

\subsection{Variable-Height Windows}
Fixed-height windows cannot follow statements that grow or shrink (Section~\ref{sec:ranges}). With the variable-height window, public edit-targeted accuracy at the default threshold rose from \smPubTgtCasAccPct\% to \bVWPubTgtAcc\% and exact file/start/end recovery on surviving targets from \bRangeDeployedPubTgt\% to \bRangeVWPubTgt\%, with no additional re-check requests.

\subsection{Compound Edits}\label{sec:compound}
A resubmission rarely applies one transformation. We composed $k \in \{1,2,3,4\}$ distinct operators on the same anchor: a move within the file or to another file, an identifier rename inside the anchor, a layout-only wrap or re-alignment, an inserted or deleted inner statement, statements inserted directly above, and a token edit nearby. Lines carry construction tags, so the anchor's final location is known by construction, and an anchor counts as changed when the syntax trees of its statements differ. Every edited file parses. To keep moves and insertions parseable, anchors were restricted to complete runs of sibling statements; this and the rejection of inapplicable operator combinations make the cells a constructed stress test, not a sample of revisions. Each cell has 300 trials per seed on two seeds (\bTwoNOne{} per $k$ pooled; Table~\ref{tab:compound}, Fig.~\ref{fig:compound}).

\subsection{Multi-Anchor Issues}
The deployed rule returns an issue for re-check when any of its anchors changes or disappears. Its consequences grow with the number of anchors. We grouped $k$ distinct real-history anchors from the same commit pair into synthetic issues (\bTwoDistinctObs{} distinct observations; the first anchor is the primary). The grouping is synthetic: anchors from one commit pair need not belong to one concern. With one anchor, \bTwoIssueRecheckOne\% of issues were returned; with two, three, five, eight and twelve anchors, \bTwoIssueRecheckTwo\%, \bTwoIssueRecheckThree\%, \bTwoIssueRecheckFive\%, \bTwoIssueRecheckEight\% and \bTwoIssueRecheckTwelve\% were (\bTwoGroupsTwelve{} twelve-anchor groups from \bTwoGroupPairsTwelve{} commit pairs). With two anchors, \bTwoNonPrimaryTwo\% of the returned issues were returned only because of a supporting anchor, rising to \bTwoNonPrimaryEight\% with eight; a policy that watched the primary anchor alone would have missed \bTwoPrimaryMissTwo\% of the two-anchor issues whose code had changed and \bTwoPrimaryMissEight\% of the eight-anchor ones, against at most \bTwoAnyMissOne\% for the any-anchor rule. The any-anchor rule is therefore necessary for safety, but on many-anchor issues it returns nearly every issue after an edit-heavy revision. The interface should show which anchor triggered the request, as the studio's per-anchor notes already do, and supervisors should prefer few, precise anchors per issue.

\subsection{Scale}\label{sec:scale}
For an anchor of $s$ lines and $q$ characters in a file of $L$ lines, in a version of $N$ lines in total, the tiers cost: a digest comparison (tier~1); $O(L\,s)$ line comparisons for the exact run search (tier~2); a line diff of the old and new file, quadratic in $L$ in the worst case, plus $2r+1$ window comparisons with $r=\max(10,2s)$, each quadratic in $q$ in the worst case (tier~3); and $O(N\,s)$ for the cross-file search (tier~4). The pinned code recomputes the normalized lines of every file for each anchor that reaches tier~4, so a composition of $A$ such anchors costs $O(A\,N\,s)$; caching normalized files per composition would remove the factor $A$ from the file scan.

We timed composition on two large public trees, Django (\bTwoDjFiles{} files, \bTwoDjLines{} lines) and the CPython standard library (\bTwoPyFiles{} files, \bTwoPyLines{} lines), relocating 1,000 anchors sampled from files changed between consecutive releases (pinned commits in the artifact). The deployed cascade needed a median of \bTwoDjDepAnchorMed{}\,ms per anchor on Django and \bTwoPyDepAnchorMed{}\,ms on CPython (95th percentiles \bTwoDjDepAnchorPninetyfive{} and \bTwoPyDepAnchorPninetyfive{}\,ms), and \bTwoDjDepComposeThousand{}\,s and \bTwoPyDepComposeThousand{}\,s for the 1,000-anchor composition. Anchors found nowhere dominate: on CPython the \bTwoPyRemovedCount{} anchors labeled \lbl{removed} took \bTwoPyRemovedShare\% of the composition time. The adversarial case, a quotation found nowhere, forces the full cross-file scan and took a median of \bTwoDjDepAbsentMed{}\,ms per anchor on Django and \bTwoPyDepAbsentMed{}\,ms on CPython. The research implementation of the three guards is not optimized (median \bTwoDjAllAnchorMed{} and \bTwoPyAllAnchorMed{}\,ms per anchor). Timings come from one workstation and are descriptive; a capstone submission is far smaller than either tree.

\section{RQ5: A Stronger Locator Inside the Safety Workflow}\label{sec:locator}
Sections~\ref{sec:external} and~\ref{sec:student} show that the cascade is not the best locator. Its change labels, two of its three guards and its issue states, however, do not depend on how a window was found. The indentation guard and the copy guard inspect only the returned window; the variable-height window belongs to the cascade's own search and has no counterpart over another locator. This section tests that separation directly: can the safety-oriented workflow improve the reliability of an already strong locator? We placed CodeMapper \cite{hu2026codemapper}, the most accurate locator in our comparisons, and the contextual tracker inside the workflow, and then a language model. Each locator returns a window or no match. The window passes through the quotation comparison that assigns the cascade's labels (\emph{labels only}: \lbl{content-match} or \lbl{moved} when the normalized quotation is found unchanged, \lbl{changed} otherwise, \lbl{removed} on no match) and then through the indentation guard and the corrected copy guard, IG+AGi. The guards never move a window, so placement stays the locator's own and only the requests change. Because CodeMapper sees one file pair at a time, we also evaluated it with the cascade's cross-file search as a fallback when it reports no match.

The protocol, adapters and hypotheses were recorded with code hashes before any guarded output was computed (protocol~I in the artifact), and each amendment was recorded before the outcomes it concerns. The guarded locators were evaluated on the real histories, the student-authored repositories, the human-annotated benchmark and a new stress seed generated after the protocol was fixed, which holds out \wiFrN{} indentation, duplicate, short-anchor and compound cases. \section{RQ6: The Implemented State Contract}\label{sec:statecheck}
The safety argument of Sections~\ref{sec:design}--\ref{sec:impl} rests on rules about who may change an issue's state. We checked those rules against the pinned application in three ways: a specification read from the code, a static scan with a bounded model check, and scenario tests that drive the application's own interfaces.

\subsection{Static Scan and Bounded Model}
A scan of the abstract syntax trees found \wpdWriters{} call sites that create, update, delete, restore or undo a review issue, and no direct assignment to an issue's status. Each was reviewed. The system writers are carry-forward, the composition merge and composition's creators; none writes \lbl{resolved}.

The bounded model encodes the transitions of Table~\ref{tab:transitions} for two findings and two versions, with the relocation label of every carried issue chosen nondeterministically. Exhaustive search to depth \wpdDepth{} visited \wpdStates{} distinct states and \wpdTransitions{} transitions. No system event wrote \lbl{resolved} (\wpdSystemResolved{} violations); revision history stayed append-only; repeated composition changed nothing; and the assistant never closed an issue without a supervisor's confirmation. One invariant failed. ``An active issue reaches the next version unless a supervisor closes it'' was violated on \wpdNotCarried{} transitions, all through deletion: \wpdNotCarriedFaculty{} by a supervisor and \wpdNotCarriedAgent{} by the assistant, with \wpdNotCarriedOther{} from any other cause. Deletion is journaled and undoable, but a deleted issue is not carried forward. The verified property is therefore narrow: no system event resolves an issue. It is not a guarantee that no concern leaves the workflow. The model abstracts the code as we read it; the scenarios below exercise the code itself.

Three claims did not hold, and the design text has been corrected accordingly.

\emph{Dismissal memory} compares a newly raised finding with the findings dismissed on the immediately preceding version only, by category and the first 200 normalized characters of the description's first paragraph; issues written by a supervisor or the assistant are keyed by title. A different finding with the same opening paragraph was suppressed; a finding absent from one version and raised two versions later arrived \lbl{open}; and a supervisor's dismissal of a hand-written issue did not suppress the detector's finding on the same code. The key is a heuristic, not an identity.

\emph{Carry-forward} reads only the preceding version's review. When an intermediate version had never been composed, its successor received none of the earlier issues until the intermediate review was composed and the successor recomposed. In normal operation every version is composed after analysis, so this needs a failed pipeline.

\emph{Normalization.} CRLF/LF changes and a removed final newline kept anchors \lbl{content-match}. A byte-order mark changed an anchor on the first line only. A file with an invalid UTF-8 encoding rejected the whole upload rather than losing anchors. An unchanged file of \wpdBigFileBytes{} bytes exceeded the carry size limit, so its anchor was labeled \lbl{removed} and returned for re-check: a false re-check, not a silent error.

The scenarios also recorded two behaviors the earlier text did not describe. When analysis raises a finding again on a carried issue, the issue absorbs it: its evidence is replaced and an active issue returns for re-check, while a resolved or dismissed issue keeps its state. And the studio's ``Compare with version $n$'' panel shows only the immediately preceding version, so after several resubmissions it compares against the last carried quotation; the original survives in the stored lineage.

\section{Threats to Validity}\label{sec:threats}

\subsection{Construct Validity}
Every outcome is a property of locations and labels, not of review concerns. A correct start line does not show that a comment still applies, and a changed label does not show that a concern is affected. The controlled edit mix is uniform over twelve operators chosen by us, and one of them, re-indent, often yields invalid or behavior-changing Python (Section~\ref{sec:stress}). Automatically sampled anchors need not resemble the spans supervisors select: supervisors may favor short, repeated or boundary-spanning lines, which the stress suites show to be harder. Changes outside the quoted range can matter to a concern and are not evaluated. The effort model's weights are illustrative, not measured costs.

\subsection{Oracle Validity}
The real-history reference is a syntax-tree correspondence procedure, not semantic ground truth: it aligns statements by normalized tree structure and uses heuristics for replacements, moves and deletions, and does not decide whether two statements behave alike. It excludes \rExcludedPct\% of candidate observations; excluded files have larger diffs (median \wpaExclDiffMedian{} changed lines versus \wpaRetainedDiffMedian{} for retained ones), so accuracy is conditional on a decidable and easier subset and may overestimate performance on unrestricted code evolution. The original manual audit covered only 40 decisions and was carried out by members of the development team, which risks confirmation bias; a 70-case blinded packet with separately held answers is prepared, but no independent responses have been collected. The human-annotated external benchmark of Section~\ref{sec:external} is the only reference in this paper made independently of the authors. Every target the reference calls unchanged keeps its quoted lines at the reference location, but for relocated targets that location can be a copy that already existed, so its identification errors can overstate missed re-checks and also hide a few: they bound the deployed miss rate between \refdirBoundPct\% and \refcopyMissPctWorst\%. Placement accuracy and unnecessary re-checks have no such bound.

\subsection{Internal Validity}
The default threshold was selected on a separate synthetic seed. Leave-one-project-out calibration, the factorial ablation and the guards' real-history results use histories that earlier revisions had inspected, so they are retrospective; the guards' held-out evidence is limited to stress suites generated after their protocol was fixed, the external benchmark and the student-authored repositories. The corrected copy guard AGi was specified after the first guard's student and compound results had been read, so its held-out evidence is the fresh stress seed of Section~\ref{sec:locator}; CodeMapper with the cross-file fallback and AGi was composed after outcomes were read and is exploratory. The guarded ten-commit replay was first run with the rejected provenance rule and repeated with AGi under a recorded amendment before its outcomes existed. The pinned CodeMapper is not fully deterministic: recomputed on the same chains, it changed its answer on \wiChIGateChains{} of 4,000, so CodeMapper rates carry a small run-to-run variation beyond their sampling intervals. The protocols are timestamped locally, not externally preregistered. The conventional baselines are reimplementations of documented behaviors, not tests of the deployed products, and implementation details of GitHub, Gerrit or GitLab may differ.

\subsection{Statistical Dependence}
Observations from the same project, commit pair or source file are correlated. Wilson intervals are nominal per-observation intervals. We therefore also report cluster-bootstrap intervals by source file, commit pair and project; one internal comparison loses its resolved direction under project clustering (Section~\ref{sec:design-results}). With nine projects, project-level intervals are coarse. The paper reports many paired comparisons and does not adjust them for multiplicity. The registered hypotheses are therefore stated per population and contrast together with the number that held (H1 was supported on \wiHypOneSupported{} of \wiHypOneTotal{} contrasts and H2 on \wiHypTwoSupported{} of \wiHypTwoTotal{}), and an individual interval that excludes zero should be read as one comparison among many, not as a confirmed effect.

\subsection{External Validity}
All real histories are Python, from four internal projects and five widely used libraries; none consists of supervised student resubmissions. Student revisions may restructure more, repeat more code, be submitted incompletely or omit files. The public student-authored repositories of Section~\ref{sec:student} are a stand-in that shares authorship but not the supervision setting. The algorithm operates on text, but cross-language effectiveness rests on the external benchmark of Section~\ref{sec:external}, not on our own corpora. Errors may accumulate over many resubmissions; our multi-hop analysis replays real commit chains without independent intermediate identity labels or supervisor intervention.

\subsection{Implemented but Not Evaluated}
Media-note reliability for users, privacy and access control and concurrent composition are implemented design controls. Section~\ref{sec:statecheck} reports the scenario tests that exercise them, which are pass/fail checks of specified behavior, not a security assessment, penetration test or user study.

\section{Discussion}\label{sec:discussion}

\subsection{What Was and Was Not Shown}
The experiments show where anchored code is found, how its change is labeled and how often the label withholds a re-check, on defined distributions. They do not show that supervisors begin a re-review faster, revisit more of their earlier points, close fewer issues in error or that students respond better. Those benefits motivate the design and are plausible, but they are hypotheses. The direct test is a within-subjects study in which supervisors re-review the same revised submissions with a conventional interface and with \sys{}, measuring time to locate earlier comments, the share of earlier issues correctly revisited, erroneous closures and workload.

\subsection{Matcher Strength}
The method is strongest where its design assumptions hold: code that is shifted, moved or edited lightly and that has no identical copies nearby. On naturally edited statements its default threshold is too strict, the earlier v1 design relocates more, an independent contextual line tracker relocates more again within files (Sections~\ref{sec:realtracker} and~\ref{sec:student}), and a dedicated region mapper, CodeMapper, locates human-annotated regions far more accurately and recovers their boundaries where the cascade mostly does not (Section~\ref{sec:external}). The cascade is not a competitive locator. Its distinctive capabilities are cross-file recovery and the labels that drive the issue state. Because the labels are computed from the evidence a matcher returns, the relocation engine is replaceable. Section~\ref{sec:locator} did this with CodeMapper: the same label rules and window guards (IG and AGi; the variable-height window is part of the cascade's own search) made it safer on every population without changing its placement. The workflow's safety properties are those of the combined system, and a deployment should pair the strongest available locator with the safety layer rather than choose between them.

\subsection{Costs of Different Failures}
The failures do not cost the same. A lost anchor is visible: the issue requests re-check and the supervisor searches for the code, a cost of time. An unnecessary re-check costs a short confirmation. A missed re-check or a silent misplacement costs attention that is never prompted, and can lead a supervisor to judge a concern against the wrong code. The evaluation therefore treats the last two as safety failures and the first two as effort, and recommends guards that convert silent failures into visible ones even at the price of more confirmations.

Whether that price is worth paying depends on how many carried issues point at code that changed, which no study here measured. Let $p$ be that share and $w$ the cost of a missed re-check in units of one unnecessary confirmation. The recommended guards (Table~\ref{tab:locator}) cost no more than the deployed cascade when $w\,p$ times the fall in the missed re-check rate is at least $(1-p)$ times the rise in the false re-check rate. With $w=1$ the break-even share is \wiRealBreakEvenOne\% on real histories, \wiStuBreakEvenOne\% on the student-authored repositories and \wiHumBreakEvenOne\% on the human-annotated regions; with $w=10$ it is \wiRealBreakEvenTen\%, \wiStuBreakEvenTen\% and \wiHumBreakEvenTen\%. These points ignore silent misplacements, which the guards also reduce on every population, so they favor the deployed cascade. For comparison, \wpeOutdatedPct\% of review threads in our open-source sample were outdated by GitHub, an upper bound on changed code rather than a measured share of unresolved concerns. A course that weighs a hidden change at ten confirmations or more gains from the guards on all three populations once more than \wiHumBreakEvenTen\% of its carried issues point at changed code.

\subsection{Misplacement as a Traceability Problem}
A misplaced anchor attaches feedback to code with a different meaning. The interface shows the label in plain language beside every relocated anchor, and the supervisor can edit an anchor; every edit is an attributed revision. When tier~3 accepts a \lbl{changed} window, however, the carried anchor's quotation is replaced by the matched text, and later versions are matched against that updated quotation. In the deployed code the original quotation survives only in the previous version's issue, reachable through the lineage reference. The multi-hop replay shows the consequence: after a wrong fuzzy update, later revisions can match the updated quotation exactly, so the latest label alone cannot certify continuity with the original target. The identity rule of Section~\ref{sec:identity} keeps the reviewed quotation in every carried anchor and, in replay, made the latest request carry the whole history (Section~\ref{sec:prefixes}). It is evaluated in replay only; the deployed portal does not yet store it.

\subsection{Media Notes}
Voice, video and image notes follow their issue or are re-found with the cascade when pinned to code. Their placement reliability is that of code anchors, and their handling across versions is covered by the scenario tests of Section~\ref{sec:statecheck}. No quantitative relocation study or user study of media notes was performed.

\subsection{Deploying the Method in a Course}
An institution adopting the method should keep the local search scope and tier order, choose the threshold as a policy between relocation and honest removal (Section~\ref{sec:design-results}), enable the indentation guard and the corrected copy guard AGi over whichever locator it uses (Section~\ref{sec:locator}), keep the reviewed quotation beside the current one, prefer few anchors per issue, warn supervisors when they anchor a recurring one-line span, and keep resolution with the supervisor. Supervisors' corrections of misplaced anchors should be logged, with consent, so that a course can calibrate locally.
\subsection{Ethics and Data Handling}
No student submission was used in this evaluation. The synthetic benchmark used our own project code; the real histories came from our projects, public open-source repositories and public student-authored repositories, all parsed and never executed. The student-authored repositories are pseudonymized here and no individual is identified. In the portal, feedback stays private to the supervisors until it is shared, and a student sees only the frozen packet addressed to them. Research telemetry in the portal is separate from course access: it requires opt-in consent, synthetic demonstration data are excluded from research aggregates, and declining consent does not change a student's access to the course. A classroom study would require institutional approval and an appropriate consent process.

\section{Oracle Audit}\label{app:audit}
The recorded audit draws 40 in-house observations with seed 7: 20 from edited, gone and moved-file classes, and 20 from preserved classes. The file \texttt{oracle-audit-v1.txt} records the compared quotations and judgments. Thirty-nine decisions were accepted; one pairing of unrelated same-type statements was marked doubtful. These are the recorded audit judgments, not an independent multi-rater validation. The sample does not establish accuracy on public-project, excluded or rare-class observations, and the direction of reference error need not favor or penalize every matcher equally.

Reproduction has three levels. First, export the pinned corpus and run \texttt{analysis\_v3.py} to regenerate controlled trials and summaries; the additional harness retains individual rows. Second, \texttt{real\_history.py} rebuilds reference observations from exact histories and \texttt{merge\_oss.py} combines the public runs. The selection-only adapter verifies the same sample and exclusions without evaluating matchers. Third, \texttt{analyze\_real.py} regenerates the real-history tables, while the controlled table/plot scripts regenerate their presentation. Re-aggregation alone does not validate reference judgments or reconstruct source histories.

The verification artifact documents commands for the reference-definition sensitivity, complete-source checks and independent tracker comparisons. The range experiment runs \path{evaluate_real_ranges.py} followed by \path{summarize_real_ranges.py}, retaining both thresholds' coordinates and the declared metric. \path{evaluate_revision_chains.py} replays the ten-hop comparisons and \path{summarize_revision_chains.py} aggregates endpoints and request histories. Their local protocols precede execution; neither is an external registration. A complete artifact must include input revisions, traversals, environment, seeds, outputs and checksums. Runtime depends on the environment; deterministic counts must match the recorded expectations. Private-source access remains a separate requirement.
